───────────────────────────────────────────────────────────────────────────────
  ЧТО ЭТО
───────────────────────────────────────────────────────────────────────────────

  Менеджер проектов для создания ZIP-архивов.

  Каждый проект — это:
    • Название (например, «Документы»)
    • Список папок-источников (1 или несколько)
    • Папка для архивов (куда сохранять ZIP)
    • Шаблон имени архива ({name}_{date}.zip)

  Программа:
    • Хранит проекты между запусками
    • Показывает статус каждого проекта (свежий / устарел / нет архива)
    • Создаёт и пересоздаёт архивы по кнопке
    • Хранит N последних архивов (опционально)
    • Помнит, когда последний раз делали архив, даже если сам
      файл уже удалён


───────────────────────────────────────────────────────────────────────────────
  ЗАЧЕМ ЭТО
───────────────────────────────────────────────────────────────────────────────

  Типичные сценарии:

    • Регулярно архивирую папку «Документы» — один клик, всё готово.
    • Каждую неделю делаю бэкап «Рабочий проект» — вижу, что архив устарел,
      обновляю.
    • Несколько проектов (Документы / Фото / Проекты / Архив) — все на
      одном экране, статус каждого.
    • Отправить папку коллеге — создал ZIP, отправил.
    • Хранить 3 последних версии — старые удаляются автоматически.
    • Залил архив в облако и удалил с диска — вижу, когда последний раз
      делал бэкап, чтобы не забыть.

───────────────────────────────────────────────────────────────────────────────
  СТАТУСЫ ПРОЕКТА
───────────────────────────────────────────────────────────────────────────────

  ✅ Свежий   — архив новее всех файлов в источниках
  ⚠ Устарел  — в источниках есть изменения новее архива
  ❌ Нет      — архива ещё не создавали
                (или архив был, но его удалили с диска —
                 тогда в «Деталях» видна дата последнего архива)
  ✗ Ошибка    — проблема при чтении, записи или с путями
  🔄 Обновляется — идёт процесс создания


───────────────────────────────────────────────────────────────────────────────
  ИСТОРИЯ ПОСЛЕДНЕГО АРХИВА
───────────────────────────────────────────────────────────────────────────────

  Программа помнит, когда последний раз УСПЕШНО создавался архив
  для каждого проекта — даже если сам ZIP уже удалён с диска.

  Где видно:
    • Колонка «Детали» у проекта со статусом «Нет архива»:
        «Архива нет. Последний был 17.10.2026 21:27 (Документы_2026-10-17.zip),
         сейчас 1240 файлов»
    • В экспорте TXT/JSON (поле «Последний успешный архив»).

  Зачем это нужно:
    • Залили архив в облако и удалили — видно, когда последний раз
      делали бэкап.
    • Переехали на другую машину, старых архивов нет — видно, когда
      был последний.

  Сбросить историю:
    ПКМ по проекту → 🧹 Забыть историю последнего архива.
    (Сам файл архива, если он есть, не удаляется.)

  История хранится в ~/.zipbackupmanager/projects.json — в полях
  last_success_at / last_success_name / last_success_size /
  last_success_files. Можно скопировать файл на другую машину —
  история переедет вместе с проектами.


───────────────────────────────────────────────────────────────────────────────
  ДИАЛОГ ПРОЕКТА
───────────────────────────────────────────────────────────────────────────────

  Поля:

    Название
      Имя проекта. Используется в шаблоне имени архива.

    Источники
      Список папок для архивации. Можно добавить несколько.
      Кнопки: + Добавить папку / − Удалить.

    Куда сохранять архивы
      Папка для ZIP-файлов. Если её нет — создастся автоматически.

    Шаблон имени архива
      Подстановки:
        {name}      — название проекта
        {date}      — YYYY-MM-DD
        {datetime}  — YYYY-MM-DD_HH-MM-SS
        {count}     — количество файлов

      Примеры:
        {name}_{date}.zip     → Documents_2026-10-17.zip
        {name}.zip            → Documents.zip (перезапись)
        backup_{datetime}.zip → backup_2026-10-17_15-30-45.zip
        data_{name}_{count}.zip → data_Documents_1240.zip

  Опции:

    ☑ Рекурсивно (включая подпапки)
        Обходить подпапки источников или только верхний уровень.

    ☑ Игнорировать скрытые
        Пропускать файлы, начинающиеся с точки, и с атрибутом hidden
        в Windows.

    Пароль ZIP
        Пароль для шифрования архива (AES-256). Требует pyzipper.

    👁 — показать пароль (переключение)
    ☐ Запомнить пароль в проекте
        Сохранять пароль в ~/.zipbackupmanager/projects.json.
        ⚠ Небезопасно — пароль хранится открытым текстом.
        Если снять — при каждом обновлении будет спрашивать пароль.

    Шифрование
        Показывает статус:
          ✓ AES-256 (pyzipper) — готово
          ✗ Шифрование недоступно — установите pyzipper

    Маска
        Фильтр по имени файла. Примеры:
          *              — все файлы
          *.docx *.pdf   — только docx и pdf
          report_*       — только начинающиеся с report_

    Хранить последних
        Сколько последних архивов оставлять. 0 = не удалять.
        Работает только для шаблонов с {date} или {datetime}.

    Исключить папки
        Имена или части имён папок, которые пропускаются.
        Пример: node_modules .git temp __pycache__


───────────────────────────────────────────────────────────────────────────────
  КАК РАБОТАЕТ ОБНОВЛЕНИЕ
───────────────────────────────────────────────────────────────────────────────

  При нажатии «📦 Обновить»:

    1. Программа обходит все источники проекта.
    2. Собирает список файлов (с учётом маски, исключений, скрытых).
    3. Создаёт НОВЫЙ ZIP-файл с нуля. Не инкрементально.
    4. Пишет во временный файл, потом переименовывает.
    5. Внутрь добавляет _zipbackup_manifest.json — список источников,
       дата, количество файлов.
    6. Если шаблон с {date} — создастся новый файл. Старый остаётся.
       Если шаблон без {date} — старый перезаписывается.
    7. Если задано «хранить N» — удаляются старые архивы по шаблону.
    8. После успеха обновляется история последнего архива
       (дата, имя, размер, количество файлов).

  ⚠ Каждый раз архив создаётся ЗАНОВО (пересборка целиком).
     Никакой инкрементальности — только полный ZIP.
     Для папок 1 ГБ — секунды-минуты. Для десятков ГБ — медленно.


───────────────────────────────────────────────────────────────────────────────
  ШИФРОВАНИЕ (AES-256)
───────────────────────────────────────────────────────────────────────────────

архивы шифруются AES-256.


  Совместимость AES-256:
    ✓ 7-Zip
    ✓ WinRAR
    ✓ Bandizip
    ✓ PeaZip
    ✗ Проводник Windows (встроенный ZIP)
    ✗ macOS Archive Utility

  ⚠ Пароль хранится в projects.json ОТКРЫТЫМ ТЕКСТОМ, если включена
    опция «Запомнить пароль». Без неё — спрашивается при каждом
    обновлении (в этой сессии — один раз).


───────────────────────────────────────────────────────────────────────────────
  СОХРАНЕНИЕ ПРОЕКТОВ
───────────────────────────────────────────────────────────────────────────────

  Все проекты хранятся в файле:
    ~/.zipbackupmanager/projects.json

  На Windows это:
    C:\Users\<имя>\.zipbackupmanager\projects.json

  При запуске — загружаются автоматически.
  При изменении (создание, редактирование, удаление, успешное
  обновление архива) — сохраняются.

  Формат — обычный JSON. Можно открыть текстовым редактором и поправить
  вручную, но лучше этого не делать — можно сломать пути и шаблоны.


───────────────────────────────────────────────────────────────────────────────
  ЭКСПОРТ ОТЧЁТА
───────────────────────────────────────────────────────────────────────────────

  Кнопка «💾 Экспорт» — сохранить отчёт:
    • TXT  — читаемый текст (список проектов и статусы,
             включая историю последнего архива)
    • JSON — машинно-читаемый (все поля проекта + статус
             + last_success_*)
    • CSV  — таблица для Excel

  Экспортируется информация о проектах (не содержимое архивов).

───────────────────────────────────────────────────────────────────────────────
  ⚠️ ЧЕСТНО О ВОЗМОЖНОСТЯХ
───────────────────────────────────────────────────────────────────────────────

  ⚠ Обновление ВСЕГДА пересоздаёт архив целиком.

    Не инкрементально. Не «только изменённые файлы». ZIP собирается
    заново с нуля каждый раз.

    Для папок 1 ГБ — секунды-минуты. Для десятков ГБ — медленно.
    Для инкрементального бэкапа используйте rsync, robocopy, restic,
    borgbackup.

  ⚠ Фонового бэкапа нет.

    Только вручную. Для расписания — systemd, Task Scheduler,
    LaunchAgent, cron.

  ⚠ Проверки целостности нет.

    ZIP создаётся стандартным zipfile. Открыть и проверить можно любым
    архиватором. Автоматической проверки SHA-256 нет.

  ⚠ Удаление старых архивов — только по шаблону.

    Если в папке лежат другие ZIP с похожими именами и опция
    «хранить N» включена — они могут быть удалены. Будьте внимательны
    с настройкой. Шаблон проверяется по имени проекта ({name}).

  ⚠ Один архив = один проект.

    Если два проекта используют шаблон без {name} (например,
    backup_{date}.zip) — они будут искать ОДИН и тот же файл.
    Могут конфликтовать при удалении старых.

    Правило: если шаблон не содержит {name} — используйте его только
    в одном проекте.

  ⚠ Пароль хранится открытым текстом.

    Если включена опция «Запомнить пароль» — пароль пишется в
    projects.json без шифрования. Кто имеет доступ к файлу — увидит
    пароль.

    Если это критично — снимайте «Запомнить пароль», вводите каждый
    раз вручную.

  ⚠ macOS Archive Utility не открывает AES-256.

    Проводник Windows и встроенный распаковщик macOS не поддерживают
    AES-256 в ZIP. Для распаковки используйте 7-Zip, WinRAR, Bandizip
    или PeaZip.

  ЧАСТЫЕ ВОПРОСЫ
───────────────────────────────────────────────────────────────────────────────

  Q: Почему архив весит больше папки?
  A: ZIP сжимает не всё (уже сжатые файлы — jpg, mp4, exe — почти не
     сжимаются). Итоговый размер может быть на 5-15% больше исходной
     папки (накладные расходы формата).

  Q: Почему обновление долгое?
  A: Архив собирается заново. Если папка 4 ГБ — придётся прочитать
     4 ГБ, сжать, записать. Это нормально для ZIP.

  Q: Как сделать инкрементальный бэкап?
  A: Эта утилита не для этого. Используйте rsync, robocopy, restic
     или borgbackup.

  Q: Куда сохраняются проекты?
  A: ~/.zipbackupmanager/projects.json
     На Windows: C:\Users\<имя>\.zipbackupmanager\projects.json

  Q: Можно ли экспортировать проект?
  A: Кнопка «💾 Экспорт» сохраняет отчёт. Проекты сохраняются
     автоматически в ~/.zipbackupmanager/projects.json — при переезде
     на другую машину можно скопировать этот файл.

  Q: Что если источник недоступен (отключён диск)?
  A: Статус будет «Ошибка» или «Устарел». При обновлении — создастся
     архив с тем, что доступно. Проверьте пути в диалоге проекта.

  Q: Я удалил архив, но программа всё равно пишет, когда он был.
  A: Это история последнего успешного архива. Если она не нужна —
     ПКМ по проекту → 🧹 Забыть историю последнего архива.
     Сам файл архива (если он есть) не удаляется.
